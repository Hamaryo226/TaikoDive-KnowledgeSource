# 08｜Launcher の適合試験

本体とは別に合否を判定する。合成インストールと Launcher 専用設定ディレクトリを用意し、履歴、プロフィール、素材、プロセス応答を合成できる箇所は置き換える。設定・更新は隔離先を実際に読み戻す。UIAだけでは細いコントローラー図形の実ポインター操作も合格とはしない。既知の実行結果は [検証記録](13-baseline-verification.md)。

## 履歴データの合成試験

| ID | 入力 | 期待値 | 元テスト・根拠 |
|---|---|---|---|
| QA-D04 | 同一有効レコードを別の `.json` に二重配置し、壊れた JSON、日付がない JSON、`.json.tmp`、`Score.dat` を混ぜる | 有効 ID は一つ。別拡張子や壊れたレコードの影響を受けず、`score:120000`、UTC オフセット 0 の日付が読める | `L/Tests/PlayActivityTests.cs` |
| QA-L01 | JST で現在日 2026-11-22。Alice の 2026-11-20 15:00Z と 2026-11-21 02:00Z、同日の Bob、翌日の Alice を投入し Alice に絞る | 365 日、2026-11-21 は 2、2026-11-22 は 0。UTC の日境界を使わない | 同上 |
| QA-L02 | UTC で現在日 2026-11-22。2024-01-01 00:00Z、2026-11-15 23:59:59Z、2026-11-16 00:00Z、2026-11-22 00:00Z に各 1 | 53 週、月曜始まり。最終週は 2026-11-16 開始で 2 件、前週 1 件。古い 1 件を含み累積 4 | 同上 |

## 実画面・更新・異常経路

| ID | 初期条件と操作 | チェックする出口 |
|---|---|---|
| QA-W05 | ランチャーを light/dark・標準幅/狭幅で開き、入力設定で 2P の項目を選択 | 1P と独立、選択したプレイヤーの割当だけが変わる。図形の狭い縁を実ポインターで操作。非表示ボタンのヒット領域が残らない |
| QA-W06 | 未保存のフォームでページ遷移・閉じる・起動を個別試験。ゲームが起動中のケースも作る | 保存・破棄・キャンセルを区別し、キャンセルが遷移と保存両方に有効。元設定の未知キー・コメント（対象形式による）とバックアップを読み直す |
| QA-W07 | 合成プレイ履歴を置いて記録画面を開く。日別/週別/累積とプレイヤーを切替。起動後に有効履歴 1 件を追加 | 五感で読める表示、軸・初期表示・日境界と実際の件数、更新操作と読取範囲。スコアだけでは回数が増えない |
| QA-W09 | 合成の更新サーバーと自分のテスト署名鍵、隔離したゲーム/ランチャー/資源を用意 | 正常更新・中断再開・整合性/署名不一致・適用失敗・復旧を試し、更新後と復旧後のファイル、保護すべき保存データを再読み込み。実サービスに故障操作しない |

互換判定は読取、書込、起動、プレビュー、修復、自己更新を独立させる。本体の判定や演奏完了の合否は [本体側の適合試験](../game/08-conformance.md) へ。両方をつないだ相互運用は [連携契約](../INTEROP.md) で別に確認する。
