# 22｜素材ローダー、メモリ寿命、文字の先読み

対象は G `fb12417`。ここでは音源のゲインや演奏表示のレイヤーではなく、どの描画リソースをいつ利用可能にするかを規定する。数値リテラルの初期化先とパスは [24](24-loader-resource-bindings.tsv)。これは固定パス・接頭辞の実装との対応表で、実際の画像・音源やすべての動的パスの一覧ではない。

## RES-01 レコードとロード状態

1. 通常のパスから作る画像は Scale=(1,1)、alpha=255。現在の遅延グループがなければライブラリへロード依頼し、該当するウォームアップリストに登録する。遅延グループがあればパス、生成時の色深度、表示状態を記録し、物理ハンドルは無効値 −1。グループ用スタックはスレッドごと、内側を閉じれば以前のスコープへ戻る。
2. 物理ハンドルのロードは「当該レコードが非破棄、ハンドル −1、パス非 null」のときだけ。生成時色深度へ一時切替し、成功／失敗を問わず以前の色深度へ復帰。専用非同期 API はロード要求を発行するだけ。「要求した」「利用可能」「欠損」は別状態であり、待機判定は有効ハンドルでロード状態が正のときだけ。
3. 画像の共有ビューは物理グラフを所有しない。読み込みは元のレコードへ委譲して現在のハンドルを借り、自分用の描画パラメーターを持つ。ビューの unload/dispose だけでは元グラフを削除しない。3D フレームビューは pose を指し、画像同様に恒久的な個別ハンドルを持たない。
4. `Unload` は状態を未ロードへ戻し、同じパスを後で読み直せる。`Dispose` は終端状態で再利用不可。画面で参照しているビューを解放対象の定義から勝手に作り直さない。`PurgeDisposedDeferredTextures` は曲再読込等で不要になったレコードをグループから除くための処理で、表示中の有効画像全体を削除する操作ではない。
5. 通常の画像・音源欠如と、起動に必要な論理データの欠如を分ける。欠損グラフは描画されず、欠損音は通常再生されない。プレイヤー3Dに必須の `Info/Chara3D.json` / `modelsPath` と対応モデル、標準BOX の `CenterText.apt` の欠如は無視されない（[13 の実測](13-baseline-verification.md)）。寸法/マスクが前提の部品は、無効ハンドルだけで「絶対に安全」とみなさない。

根拠：`G/src/Core/Rendering/Texture.cs::Texture,tBeginDeferredGroup,tEndDeferredGroup,tEnsureLoaded,tEnsureLoadedAsync,tLoadDeferredGraph,tUnload,tCreateSharedView,Dispose`、`G/src/Scenes/Loading/TextureLoad.cs::tPurgeDisposedDeferredTextures,tLoad3Dキャラ`。

## RES-02 いつ読み、いつ手放すか

| グループ | 読み込み | 解放・保持 |
|---|---|---|
| Common | 起動時にロード要求。起動ページは曲スキャンと非同期待ちを並行処理 | 通常はゲーム中再利用。描画の共通初回ウォームアップの登録表は初回後クリア |
| `listDeferredEntry` + `Texture/Entry/Bg` | デモから、タイトルで必要になる前にロード。背景は独自のアニメグループ | タイトルとデモの間は保持、その外では通常スコープを解放要求。背景アニメは個別に Dispose |
| `listDeferredResult` | **演奏シーンに入った時点**で結果用素材の読み込みを開始。演奏中に参照する素材も含む | 演奏→結果では保持。どちらでもなくなったら解放要求 |
| `listDeferredAI/Dan/Tokkun` | 明示モード確定後だけ。有効 enum のゼロ値 AI を「確定済み」と取り違えない | 使用しないモードの解放を許すのはタイトル／通常選曲。段位や演奏中のモード状態だけで即解放しない |
| `listDeferredCourseSelect` | 通常は選曲から難易度を開く際に非同期。ポーズから同じパネルを使用するときは同期 | 選曲・段位選択の外では解放。演奏中にポーズのオプション画面を開いている間は保持 |
| `listDeferredSongSearch` | 検索を初めて開く際に要求 | 閉じる処理に従い保持／解放。開閉アニメ中に必要な絵を先に解放しない |
| `listDeferredGenreImage` | ジャンルの動的画像は描画で必要になった時に要求 | 曲再読み込みや古い画像定義の更新と結び付ける。全ジャンル画像を常時強制ロードしない |
| `listDeferredEnso` | 起動時は定義のみ。曲決定後ロード、使用可能なものを全待機後、風船の初回描画を準備 | 一度準備できた通常演奏群は曲間で同じ定義を再利用。曲別歌詞・動画・ダンサー等とは寿命を分ける |

不要になったグループはロード済みフラグを落とし、未登録なら FIFO の解放待ちへ入れる。メインループの1回で **先頭のグループだけ最大8件** `Unload`。残りが8件未満でも同じフレームで次グループは処理しない。再び必要になったら先に解放待ちから外す。すでに解放済みのものだけロードし直し、残っていたものはそのまま。たとえば10個の群を解放中、1フレームで8個解放した後に再使用なら最初の8個だけ再ロード。古い解放要求を残して新しい使用者から絵を取り上げない。

**風船の初回描画**：通常演奏グループの正の非同期状態がすべてなくなるまで `ready=false`。その後、風船画像・枠・数字・虹全コマに加え、連打中／成功／未達の3モーションを予約する。2D AI は全コマ、3D は各モーション先頭・整数中央・末尾。ロード不足のAIは待たず、負ハンドルの対象はウォーム済み集合から除く。透明で描画しても（初回描画パスを実際に通す）表示には加えない。同一レコードは再ロードを除き1回、3D 描画は1呼出し最大1コマ、残枠ありなら `ready=false` を返し次フレームへ。

**タイトル背景**：`Texture/Entry/Bg` 直下の `.aup2` をパス順（奥→手前）。有効なものだけを保有し、少なくとも1枚かつ保持した全レイヤーが非同期ロード状態を脱するまでは `Back01.png`＋`Back02.png` の代用表示。最初に描けるフレームで共有の ms カウンターを開始し、各層の時刻は `((ms×fps)/1000) mod その層の総フレーム数`。開始点・周期は別で、全層を最短素材の周期へ強制同期しない。退出で破棄し次回は頭から。[演奏中のコラボ背景](06c-glb-and-themes.md#コラボ背景)とはロード・再生条件が異なる。

根拠：`G/src/Common/Program.cs::EnsureModeTexturesForScene,EnsureCourseSelectTexturesForScene,EnsureSceneTexturesForScene`、`G/src/Scenes/Loading/TextureLoad.cs` 179–279、308–433、895–917、`G/src/Scenes/Title/EntryBgAnime.cs::tApply,bDraw,fコマ位置`。

## RES-03 動的パスとフォールバック

| 種類 | ファイル規則 |
|---|---|
| 連番 PNG | 基本の枚数は `0.png` から存在する限り1ずつ。途中が欠けたら以後を数えない。AI共通キャラは元の配列長を維持し、間引き係数 n で index が n の倍数の物理画像だけ置き、他は直前の共有ビュー。同一フォルダーを複数モーションが指すときは大文字小文字を区別せずロードを共有 |
| 名前札のフォルダー | `Texture/NamePlate/Plates/<整数>` だけ。`00` と `0` は同じ数値キーで両方ある場合は有効な後のものが勝ち、列挙順は依存しないことを前提にしない。`Anime.aup2` が存在して有効ならそれだけ、無効の場合は破棄して `Base.png` を試す。両方ない型は登録なし。任意 `PlateConfig.json` の `adjustX`/`adjustY` を元の配置に加算、読取失敗は0。登録された型の旧連番画像は空配列として読み込まない |
| 基本ぷちキャラ | `Texture/PetitChara.png` の全シートではなく、タイプ i から `x=(i mod 5)×512`,`y=(i div 5)×256`, `w=512`,`h=256` の範囲を切って保持。指定範囲が画像外なら `InvalidDataException` |
| 個別ぷちキャラ | `Info/Chara3D.json` のユーザー設定→共通→旧 `CharaConfig`、ID>0で `Texture/PetitChara/<十進ID>.png`、欠損または ID≤0 は標準。正ID用キャッシュは2件まで、新規3件目で最後に手に取ったIDではない方を捨てる。欠損でも標準への参照は記憶するが、個別廃棄で標準を二重に捨てない |
| 音源 | 固定パスは [24](24-loader-resource-bindings.tsv)。2P フルコンボ/全良ファイルは専用を優先し、失敗なら対応1Pファイルで別ハンドル。2P のクリア/ミスはそもそも同一ファイルを別ハンドルで持つ。SE 同時発火を単一共有ハンドルに潰さない |

`TextureLoad` の背景だけ 16 bit スコープは背景設定が真かつ全体16 bitでない場合に一時使用。配下の遅延定義にその色深度を記録する。終わると32 bitへ戻す。非対象の淡色グラデーションを一律16 bitに変えない。根拠：`G/src/Scenes/Loading/TextureLoad.cs` 131–176、502–560、1827–1875、`G/src/Common/NamePlate/NamePlatePlate.cs` 21–145、`G/src/Scenes/Loading/SoundLoad.cs` 246–254, 351–354。

## RES-04 文字キャッシュとキャンセル

曲名は選曲通常フォント42/縁11、BOX51/縁14、副題24/縁6、難易度の副題32/縁8（大江戸設定を使う）。通常曲の従来間隔 −12.9、BOX −17.1、副題 −7.6、指定がある場合は指定値。選曲バーの上限幅は794、難易度1140、ロード側の表示幅1593は別経路。幅がはみ出すと、上限÷原幅を 0.01 刻みで切り下げて下限0.1。同率を縦横に掛ける。中央描画は左上座標 `int(centerX−w×scaleX/2),int(topY+h×(1−scaleY)/2)`。表示の縮小をラスタライズ前の文字切捨てに替えない。

曲の先読みは中央インデックスの右1、左1、右2、左2、…左右7。BOX一覧と同じ循環。左右同じ位置の offset ではその一回だけ、別 offset 同士の重複は要求側で処理。各曲は曲名→副題（空でなければ）、中央選択が変われば近傍キューを作り直す。物理描画スレッドには Bitmap 生成を流し込まず、共有フォントの描画はワーカー1本。キャッシュキーで参照済みと重複予約を排除。処理中・完成待ちを含め最大64件で、満杯はその要求を入れない。描画まで未完成のバーは空のまま表示し、以後のフレームで再要求できる。生成失敗で予約を外す。完成したものの GPU 化は毎フレーム最大2枚、登録済みなら二重登録せず Bitmap を破棄。

生成済みはアクセス順キャッシュ、最大800件か推定128 MiB（幅×高さ×4）。削除時に GPU の実体も解放。全消去時は世代を増やして待ちキュー・予約を消し、完成未転送画像を破棄。後から古い世代のワーカーが終わっても登録しない。新世代の同キー予約を古いワーカーで消さない。根拠：`G/src/Scenes/Title/TitleKey.cs` 30–90, 138–160, 234–419、`G/src/Scenes/SelectSong/TitlePreloadQueue.cs` 20–72、`SelectSong.Recovery.cs` 86–89。

## RES-05 描画専用3Dプレビューのプロセス契約

起動の第1引数が `--character-preview` の場合は通常の画面・サウンド・DirectInput・XInputを初期化せず、表示しない描画ウィンドウのみ用意する。トークン列はモード・要求JSONパス・出力PNGパスの3個。個数不一致なら終了2（描画しない）。JSONの `modelsPath` からモデルを作り、配色・パーツを読み、`secondPlayerFacing` が真なら2P側の向きを使う。基底はプロセスの作業ディレクトリ。ただし運用では生成側が絶対パスを渡す。終了時にネイティブ描画を閉じ、通常ゲームのログ・設定・スコアは更新しない。

- `animation` が空なら `don_normal` の0.35秒を1280×720の描画先に出力。`alpha > 8` の画素の最小外接矩形を各方向24px拡張、元画像境界へクランプして保存し終了0。描画結果が無ければエラー。
- `animation` が有効名なら秒の長さ D は有限正値。`N=clamp(ceil(min(D,5)×24),2,120)` 枚、コマ i の時刻 `D×i/N`（末尾時刻 D は含めない）。各フレームを480×270へ縮小して最初は指定PNG、2枚目以降は `指定PNG.1.png`、`指定PNG.2.png` という名前。全フレームの `alpha>8` の画素を総和で囲み、各方向12pxを付け、同一矩形で全フレームを切る。個別にトリムしてキャラの中心が揺れる実装にしない。完了マーカーは指定PNGに `.animation.json` を継ぎ足したファイル、`duration`（秒）と `count`（枚数）を持つ。
- 不明なクリップ、モデル不良、描画エラーを捕捉したら、出力PNGのパスに `.error.txt` を継ぎ足したファイルにメッセージを書き終了1。出力パス自体が解決不能、またはエラーファイルを書込不能の場合はこの終了契約を保証しない。途中のPNGが残り得るので、呼出し元は終了コードと要求した成果物の組で成功を判定する。ループ再生やフレーム送りはランチャー側の責務で、このプロセスは再生中に常駐しない。

根拠：`G/src/Common/Chara/Model3D/DonModelPreview.cs` 15–155、`G/src/Common/Program.cs::Main`。隔離したモデルでの実測は [26](26-r2-verification.md)。

## RES-06 受入例

- リトライを含めて役割の違う素材を同名グラフとして共用した場合、片方のビュー破棄で他方が消えない。解放済みの物理所有者を要求し直すと同じファイルが再読込される。
- 風船グラフ1枚が欠けても、有効ハンドルでない不足を「永遠にロード中」としない。ボトルネックの調査では初ヒット・成功・ミスの各イベントを別に観測し、平均FPSだけでタイミングの一致を判定しない。
- 連番 `0,1,3.png` は長さ2。名前札に有効な `Anime.aup2` と `Base.png` の両方がある場合、下地を二重描画しない。アニメ不成立は `Base.png` 一枚へ。
- キャッシュをクリアした後、クリア前に着手した Bitmap が戻っても再表示しない。次フレームから新しい世代で同じ曲を描ける。実機のフレームの描画済み枚数とプロセスの生存確認は別の記録とする。
