# 02d｜時計・オプション優先とノーツ描画の補足

02章・03章の抽象説明を以下の参照版 G の具体式で補う。μs は単調時計の時間、演奏 tick の値は ms に相当する整数、描画値だけその小数を用いる。

## PLAY-D01 カウンターの剰余と位相

開始時は指定初期値（省略0）、端数0、基準時刻を現在の高精度カウントへ更新し動作中とする。Stop は動作フラグを落とし、Reset は動作停止・整数値を指定値（既定0）・端数0。停止状態で tick を呼ぶと時刻基準だけ更新。間隔 I が非正/非有限、または経過 e が負/非有限なら、その tick は基準を現在に直すだけ。動作中は `steps=floor((now−lastBase)/I)`。1 刻み未満なら整数はそのまま、端数 e/I。`remaining=max(1,end−value)` とし、`steps<remaining` は value+=steps。達した場合、非循環は end、循環は `start + (steps−remaining) mod max(1,end−start)`、すなわちループでは end を描画値として含めない。基準は `now−(e mod I)`、端数は終端/折り返しに達する前だけ `(e mod I)/I`、他は 0。速度変更は旧間隔で1回 tick、変更し新間隔でも tick。判定とチップ処理は整数、座標描画や HBSCROLL は整数＋端数。

音声は最初に時計≧0 で、非段位かつ未開始時に曲位置を渡す。非同期展開中は譜面時計を止めず、曲再生だけを最大30000ms待ち、その時点の譜面位置へ seek して試行する。時間切れ・失敗経路は [19](19-audio-runtime.md)。段位は BGMCHANGE が切り替え、停止／再開は曲内のサウンド位置と全体時計を混同しない。根拠：`G/src/Core/Util/Counter.cs` 36–140、`G/src/Scenes/Game/NotePlay.cs::SongPlay,tSpeedChangeInit`、`G/src/Scenes/Pause/Pause.cs`。

## PLAY-D02 ランダムと入力の優先

| 選択 | 色・サイズの処理 |
|---|---|
| でたらめ | 選択プレイヤーの譜面を格納順に一周。Notes チャンネルの小ドン/カは {1,2}、大ドン/カは {3,4} の等確率抽選。他の音符に抽選を適用しない |
| きまぐれ | 各チップについて色の条件より先に 0〜99 一様の整数を引く。65 以下（66通り）のときだけ上の再抽選を適用。同色も選び直し得る。通常音符の実際の反転確率は33% |
| あべこべ | ランダム両種がない場合だけ小・大それぞれドン/カを交換する |
| 無選択 | 元の音符値に戻す |

この変換関数は `p` で対象譜面・難易度を選ぶが、オプション参照は **1P の `OptionConfig`**。新実装で個人別表示があることから、この関数も1P/2P別参照と推測しない。時間・コース・空白を置き換えない。ゲームの乱数ストリームが同じことをテストしない場合は、「同じ抽選結果列」を明示入力とし、OS の乱数シード初期値は合否から分離。

手入力の通常ノーツは、最も近い候補探索の段階で打色をフィルターしない。打てる候補があり同色なら判定を反映して消費、別色なら消費しない。不可窓内の同色の不可はその音符の不可になる。バトンタッチ中のオート担当での有効候補はお手付き経路。通常入力の打音と太鼓の発光はヒット成立とは独立、二人演奏/AI は上レーンを左、下レーンを右へ振る。ローディングの開きが閾値に達するまで打音は出さない。機械入力では大音符を左右に光らせる。ポーズ中または特訓の停止中はこの入口を通さない。根拠：`G/src/Scenes/Game/NotePlay.cs` 768–822、866–952。

自動の単音は未処理で現在整数時刻≧chip時刻＋遅延（P1 は0、P2/AI 経路は `dbAIJudge`）になった描画処理で打ち、手を左右交互にする。手動レーンでは現在時刻がチップ以後で判定が通り越しになり、未処理ならミス。ポーズ中・特訓停止中・再生リプレイ担当はこの自動ミス経路を実行しない。自動処理を通常の手入力より後ではなく、元の描画→Update の順序で行う。風船のオートは開始〜終端内に入り、`now > start + (125/6)ms×既ヒット数` で、要求数に未達なら1フレームで1打を交互に処理。風船の人入力は通常1Pは面のみ、2P独立側はコード上4打すべてを取り得て、優先は左面→右面→左縁→右縁。端を過ぎ、風船がまだ表示中なら失敗キャラ演出を開始、風船表示フラグを落とす。根拠：`G/src/Scenes/Game/Objects/DrawNotes.cs` 123–217。

## PLAY-D03 HBSCROLL と画面基準

HBSCROLL は通常スクロールの代替で、現在積分 P をプレイヤーに応じた BPM 項目から補間する。1P・AI は P1 分岐、通常2P は2P分岐、ゴーストは記録分岐。BPM 表のキー0から開始し、正のキー側は時刻0（全分岐扱い）か該当分岐のみを候補とし、次の項目の時刻が現在より大きければ直前項目を採用。同時刻ちょうどでは新しい区間に進む。表が空、必要なキーが欠ける等の経路は 0 を取り得る。該当分岐の次項目が走査途中で尽きる実装のフォールバックは、表件数−1 のキーがあればその値を使う。採用項目の開始は内部番号0のみ `−1000×OFFSET`、それ以外は項目時刻。`P=項目に保存された積分 + (描画現在時刻−区間開始)×区間BPM/15000`。横方向差は `62.5×(チップ積分−P)`。対象の単音と小節線では通常式の Speed/NotesPosition は上書きされる。HBSCROLL フラグを BMSCROLL 別名と解釈しない。`G/src/Scenes/Game/NotePlay.cs` 987–1072、`DrawNotes.cs` 75–102。

### 判定候補探索の端点

対象レーンごとに候補リストの同一性、前回時刻、探索開始位置、開始位置未満の最後の可視連打を覚える。リスト変更または時刻が戻ったら初期化。現在−2000ms より古い位置だけ進められる。ただし可視で `bHit=false` の小・大ドン/カ、または可視で `bHit=true` かつ終端ありかつ終端>現在の連打系は飛ばさない。可視の連打系を飛ばすときは最後の位置を覚える。連打系は小・大連打、風船、くすだま。

前向きに、未処理で時刻が現在以下の通常音符を見つけるたび手前候補を更新し、現在より先の最初の未処理音符で止まる。既に打ち始めて継続中の連打系が途中にあれば、そこを手前候補にして止まる。手前候補が決まらなかった場合に戻り走査が確認するのは配列先頭の1項目だけで、その項目が可視連打系か未処理通常音符なら採る。決まっていれば後ろ向きに可視連打系または未処理通常音符で止まり、探索下限に達した時だけ保存済みの連打位置を使う。

候補2つのときは整数化した絶対時間差の小さい方、同値は手前。後が近くても、手前が未消費で符号付き遅れが不可窓以下なら手前。最後に、後候補が小・大連打または風船で開始≤現在≤終端なら優先（くすだまはこの上書き条件に含めない）。片方だけならそれを返し、どちらもなければ null。探索では色で分けない。根拠：`G/src/Scenes/Game/Objects/GetNoteProcess.cs` 42–100、121–214。

通常式の横方向差 d は 02 の式。単音は `(529+d,287+264×レーン)`, 切出し `(195×音符番号,195×口パク行,195,195)`。譜面の文字「ド」「カ」等は `(535+d,482+264×レーン)`, 切出し `(0,50×音符声番号,165,50)`。ドロンは絵のみ消し、通常音符の文字は描く。小節線は `(529+d,288+264×レーン)`。可視範囲の差 d は、通常音符が −520〜1390、小節線が −540〜1380、いずれも両端含む。描画はチップの後ろ側から逆順。判定枠は上 (521,287)、下(521,551)、195×195。AI と右太鼓側のゴーストの表示レーンを論理プレイヤー番号と直結しない。

間引ける譜面（時刻非降順、分岐なし、非HBSCROLL、各有効速度≥0.001）では、走査の時間長を `max(20000ms, 1420×419/(2.5×abs(BPM×SCROLL)) の最大)` としてオフセット絶対値を加える。未来側は二分探索で範囲開始を決め、過去側はその窓より古いチップから打切り。ただし終端が窓に残る連打は処理を保つ。これは互換のために判定候補を取り除く規則ではなく、元の描画・更新一体経路での最適化条件。根拠：`G/src/Scenes/Game/Objects/DrawNotes.cs` 10–121, 168–217、`Lane.cs` 101–103。
