# 10｜資源目録の読み方と素材再配置

## ASSET-01 基準と使い方

`11-asset-inventory.tsv` は A の固定コミットの `src/` に存在する相対パスの完全目録。配布時の配置候補は `src/` を剥がしインストールルートを前置する。「配布対象か」「必須か」は配布仕様および素材ロード仕様が正本であり、目録だけで必須扱いしない。Git blob SHA-1 は `blob `、十進バイト長、NUL、原バイト列の順に連結したものの SHA-1 で、配布物検証で使う SHA-256 とは別。アセットのバイト列自体は同梱しない。

| インストール下の分類 | A の追跡点数 |
|---|---:|
| `Info/` | 1,675 |
| `Songs/` | 54 |
| `Sound/` | 213 |
| `Texture/` | 3,502 |

合計 **5,444 点**。A は任意のローカル楽曲ライブラリ全体ではない。同じ UI 表現を得るには同一内容の画像・音声・フォント・GLB、楽曲は対応する TJA と音声が別途必要。見た目の自己検証には、同名別内容のスタブを入れてテストを完了扱いしない。

## ASSET-02 原実装が参照するパスの逆引き

`12-static-resource-paths.tsv` は G/L の実装テキスト上で `Texture`・`Sound`・`Info`・`Songs`・`Resources`・`Libraries` から始まる固定文字列（接頭辞を含む）を抽出した **533 件**。大小を無視したファイル名の一致を A と照合した。ディレクトリ、末尾に変数を連結する断片、ユーザー生成ファイル、G にのみ付くファイルを含む。「―」は不備の意味ではない。実行時の動的に組み立てるパス、フォルダーで選択されるファイル、GLB 内部参照は固定リテラル表の網羅対象ではなく、素材仕様の規則を適用する。識別子の原表記と実際に使う文字の大小は別々に確認する。

## ASSET-03 置き換え・省略の扱い

- 固定ルートは `Texture/`、`Sound/`、`Songs/`、`Info/`。同一フォルダーの素材名・付属する設定・従属ファイルの関係を保つ。TJA の `WAVE` やアートワーク、段位の参照先は単独ファイルとして散在させない。
- 複数ファイルで一つの演出になるフォルダーを部分的にコピーすると、選択肢一覧には載っても描画が欠けることがある。必須/任意・欠損時の挙動は媒体の章の規則に従う。追加素材は OS ごとの大小区別とディレクトリ巡回を意識して登録する。
- `Info/` には配布する画像・モーション・設定と、更新が保護すべき既存ユーザーデータの両方がある。全削除・全上書きをフォールバックにしない。アーカイブ、編集プロジェクト、サムネイルキャッシュなども元ツリーには存在するが、汎用ディレクトリ列挙を演奏ロードの仕様にしてはならない。
- 音声・画像を合法に用意できない場合は、無音や単色の合成データで論理試験だけを行い、視聴覚互換を未検証とする。元のメディアを推測で復元したとは扱わない。

根拠：`A/.github/workflows/publish-assets-update.yml`、`A/src/` の Git tree、`G/src/Scenes/Loading/TextureLoad.cs`、`G/src/Scenes/Loading/SoundLoad.cs`、`L/tools/assets-update/New-TaikoDiveAssetsUpdate.ps1`。パスの抽出用プログラムや原ソースは納品対象外。
