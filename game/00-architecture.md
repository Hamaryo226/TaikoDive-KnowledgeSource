同等性は次の三層で判定する。① **論理**：同じ入力で同じ選曲・ノーツ・判定・記録。② **データ**：既存データを相互に読み書きし、既存の意味や共有先を変えない。③ **表現**：同じ素材、論理座標、時間・順序で表示し、同じタイミングで音声を要求する。OS 固有のウィンドウ枠、フォントラスタライズ、音声ドライバの実機出力遅延、未提供素材の画像/楽曲/3D バイト列は、文章単独では同一にできない。これらは②・③から黙って省かず、元の互換素材・環境で別途検証する。Windows 固有の更新やコントローラー列挙は、同一観測結果を担うアダプターとして扱う。

## SYS-02 境界と所有権

| 部分 | 受け入れるもの | 外に出すもの／責任 |
|---|---|---|
| ゲームホスト | 起動オプション、ディレクトリ、OS イベント、論理画面設定 | シーンの生存期間、入出力アダプターの開始・停止、メインフレームの順序 |
| 曲カタログ | 曲ルート、`.def`、TJA ヘッダ、並び順設定、最近の演奏 | フォルダーと曲のツリー、検索結果、選択された譜面・コース。演奏開始までは全文解析とリソースの寿命を分ける |
| 譜面デコーダー | 選択ファイル、コース、プレイヤー、オプション | ノーツ／制御チップの順序、開始時間、スクロール情報、分岐、曲・段位情報。ファイルの状態によって結果を分岐させる |
| 演奏コア | チップ列、プレイヤー別の設定と入力、演奏時計 | 打撃イベント、判定、レーン状態、ゲージ、スコア、結果。画像・音声アダプターの成功をスコア更新条件にしない |
| 表現・素材 | シーンと演奏の状態、論理座標、画像/音/モデル | フレーム、SE/BGM、音量、素材のロード/破棄。処理しきれない素材解放は、演奏同期を止めずに後続フレームへ分ける |
| 永続化 | 設定、ユーザー、曲の結果、操作イベント | スコア・リプレイ・段位履歴・ランチャー用プレイ履歴。プレイヤー帰属と通常・オート・中断の区別を維持 |
| 配布 | バージョン付マニフェスト、パッケージ、配布アセット | ゲーム本体と Assets を独立した版で公開する。更新を適用する外部クライアントが利用する形式を守る |

本体は作業ディレクトリにゲームの配置先を指定して直接起動できる。Launcher の内部処理は実行時の前提ではない。共有ファイルと外部起動の接続点は [連携契約](../INTEROP.md)。

## SYS-03 時計と更新順

三種類の時計を分離する。① 単調時計は UI カウンター・フェード・フレーム測定、② 曲の進行は演奏時計（速度、一時停止、シーク、オフセットを加味）、③ ローカル暦および UTC は保存時刻、集計、ログ名。OS の日時補正を演奏時刻に伝播させない。符号付き誤差、閾値の `<` と `≤`、整数除算・切り捨て、浮動小数点の精度、同時刻チップ順を他言語任せにしない。リプレイや保存の数値は形式の章が優先する。

G の通常フレームの順序は以下。移植で処理を複数スレッドに分けても、入力・状態・合成・記録の観測順は維持する。

1. OS メッセージを処理し、終了・再起動を判定。背面描画面をクリアし、キーボード、マウス、音量 UI を更新する。非同期プレビューの破棄待ちを回収する。
2. シーン移動で不要な検索・設定を閉じる。タイトル／通常選曲／段位選択で F4、条件を満たす通常選曲で F3。設定のキー取得、曲検索の文字入力は一般ショートカットより優先する。F12（DxLib のキーコード 88。元コードのコメントにある X ではない）の画面保存要求、M のメモリ計測、N の曲名キャッシュクリアは曲検索中に受け付けない。
3. シーンに必要な遅延素材の準備、順次破棄、曲名テクスチャと 3D キャラ素材のメインスレッド側コミットを進める。デモとタイトルに限りコイン・サービスクレジットをシーン描画より前に集約する。
4. 現シーンを処理して描く。選曲はゲーム内検索の上に設定、段位受付は一覧・導入の上に設定、演奏は演奏面の上にロード/導入を重ねる。結果は P1 譜面の段位フラグで段位結果／通常結果を切り替える。音量表示、全体フェード、通信状態マーク、対象シーンのみのクレジット、黒素材未準備時のロード表示を後から重ねる。
5. フレーム全体が揃ってから画面取得、E2E 観測の順に行い、それから Present し、FPS 上限の待ちを行う。演奏中の単調時計を描画回数で代用しない。終了時は音量サーバ・コイン・3D・ランチャーブリッジ・描画を終了し、フレームログの終了待ちは 1 秒上限。

元の実装は固定 **1920×1080** の描画面・32 bit を使い、フルスクリーンとサイズはウィンドウ寸法で表す。コントローラーの取得は DxLib の入力再列挙から分ける。初回ロードは曲走査と素材 I/O を並行に進め、双方の終了前はローディング描画とメッセージ処理を継続する。主ゲームの演奏・結果用素材は曲決定以前に全量を強制ロードしない。

## SYS-04 移植の着手順と交差境界

| 段階 | 成果物 | 次へ進む条件 |
|---|---|---|
| 1. データ | 素材と設定の読み口、譜面の正規化、スコア／リプレイ読み書き | 無描画で、複数コース・2P・分岐・段位・不明項目の処理が合う |
| 2. 演奏 | 擬似時計と打撃入力を持つ演奏コア | 早い/遅い境界、HIT/未打、連打・風船、分岐、2 人のスコアを再現 |
| 3. シーン | メニュー、選曲、難易度、Pause、結果をつなぐ | 選曲から戻る先、未決定状態、キャンセルと完了保存の差が合う |
| 4. 表現 | スプライト/3D、フォント、音声、デバイス | 実環境で画面と入力を確認し、曲の再生と打撃判定に回帰がない |
| 5. 配置と配布 | 隔離したゲーム配置先に本体と Assets を展開し、配布パッケージを個別に作成 | Launcher なしの直接起動とデータの読み戻しを合格させる。Launcher の適用試験は別 |
| 6. 開発版（任意） | 明示選択の D プロファイル | 主仕様の回帰がなく、D 固有のファイル・画面・統合要件を別に通過 |

**外部依存の置換**：元環境の C#/.NET 10、DxLib は再使用不要。置換するのは描画、サウンド、動画、フォント、パッド、ウィンドウ・プロセス、ファイルシステムなどのホスト境界で、譜面命令やファイルの互換規則は置換しない。異なる OS では、バックスラッシュを画面表記として残すかは任意だが、既存データ中のパスは区切りを解釈し、末尾ドット・大文字小文字・Unicode の扱いは比較仕様を明示して実装する。Unicode を一律正規化するとファイル同一性や検索結果を変える場合がある。プラットフォームの標準値を使っただけでは互換としない。

**作業データ**：この配布物にはユーザーのローカル設定、履歴、スコア、原曲、画像、モデル、フォント、実行バイナリを含めない。プログラムの挙動とリソースのインターフェースを再構築できるように記し、原素材の内容そのものは権利と取得経路を確認して別に用意する。元ソース参照記号は監査用の根拠であって、実装手順の代用ではない。

根拠：`G/src/Common/Program.cs::Main, App`、`G/src/Core/Game/GameScene.cs`、`G/docs/architecture.md`、`G/docs/adr/`。章内の「提案」は移植設計、「静的」は固定コミットのコードと設定から確認した挙動、「実測」はこの文書作成時に実行して得た結果を指す。区別のない値を OS 固有の差から推定して埋めない。
