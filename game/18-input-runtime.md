## 更新と押下

| 対象 | 確定仕様・証拠 |
|---|---|
| キーボード | `KeyInput.Update` は256状態を毎更新取得。成功時、押下中なら各カウンタを1増加、未押下なら0。`IsPush` はカウンタ=1、`IsPushing` は>0。押しっぱなしの edge 再発火はない。配列の判定は各要素の論理和。 |
| 取得失敗 | コントローラー更新後にキーボード取得が失敗すると、キーカウンタはそのフレーム更新されない。従って直前の1が残ることもある。 |
| repeat | 共通入力層にOSキーリピートの間隔や周期はない。hold は各フレーム真、edge は初回のみ。呼出元独自の連続操作と混同しない。 |
| キー取得 | `GetAnyPush` は番号0から255の順に初回edgeを返し、なければ-1。同時の全件列挙ではない。 |

## 固定UIと再割当

| 操作 | 入力と証拠 |
|---|---|
| 演奏スロット | `KeyInput.IsPush(config, slot)` はスロットのキーボード群とコントローラー群のedgeのOR。`IsPushing`も同様にholdのOR。片方の再割当で他方は消えない。 |
| デフォルト | スロット順は縁左、面左、面右、縁右。1Pは `[32] [33,34] [35,36] [37]`、2Pは `[44] [45] [46] [47]`。根拠 `G/src/Common/Config/ConfigInI.cs::KeyBindConfig`。 |
| UI例 | タイトル、選曲、難易度選択などは固定番号32/37や33/36を直接読む箇所がある。設定オーバーレイはEsc 1、上下200/208、左右203/205、Enter 28、Tab 15等。演奏キーを変更してもこれらが自動的に変化するとは限らない。`Title`, `SelectSong.Input`, `CourseSelect`, `SettingsOverlay`。 |
| クレジット | `Program.tクレジット入力を処理する` は201 PageUpで投入、199 Homeでサービス、209 PageDownで減算。ソースコメントのテンキー説明より数値・ラベルを優先。 |

## コントローラー

| 事項 | 確定仕様・証拠 |
|---|---|
| 毎回の再列挙 | `ControllerInput.Update` は `RawGameControllers` の現在順に状態を同期。消えた参照は除去、新参照は挿入、既存参照は移動する。参照同一性で一時状態を維持。読取例外時は未初期化に戻し次回同期。 |
| 初期化 | 初回読取成功時は現在ボタン・スイッチを前回へ複写するので、接続時に既に押下中のものはedgeにならない。holdは成立する。 |
| 入力 | button edgeは現在trueかつ前回false。switch edgeは現在がCenter以外かつ前回と異なる；別方向からの直接遷移もedge。割当switchのholdは現在値の完全一致。indexは0始まり、表示B/Sは1始まり。 |
| switch値 | 0 Center、1 ↑、2 ↗、3 →、4 ↘、5 ↓、6 ↙、7 ←、8 ↖。斜めは対応する上下左右の同時成立ではなく独立値。 |
| axis閾値・帰還 | 本体はaxis配列を読取に渡すが、axisの値をedge/holdや割当に使用しない。よって閾値もヒステリシスも中立復帰条件もこの版には存在しない。軸をボタン化する閾値を推測して実装しない。ドライバが別途button/switchとして露出する場合はその状態に従う。 |
| 永続identity | `FindMatchingState` はvendorId・productId一致の現在列挙中、同一VID/PIDの0始まりordinalで一致。deviceIndexとdeviceNameは判定に不使用。シリアル等の恒久個体IDではなく、同型機の順序変化・抜差しで割当先が入れ替わり得る。 |
| 検出順 | `GetAnyPush` はデバイス列挙順、各デバイスでボタン昇順、次にswitch昇順の最初のedgeだけ返す。 |

## 設定・同時入力

| 事項 | 確定仕様・証拠 |
|---|---|
| 1P同時 | `NotePlay` は4スロットそれぞれのedgeを記録する一方、面左右同フレームなら面左優先で面処理1回、縁も左優先で縁処理1回。面と縁は別のifで処理。特訓等の条件分岐は別途適用。 |
| 2P | 2人モードかつゴースト再生中でない場合に2Pスロットを読む。面左右・縁左右はそれぞれ左優先で1回ずつ。特訓停止中は通常打撃を処理しない。1Pのリプレイ中入力抑止と2Pゴースト条件は同一ではない。 |

## マウス・DPI

| 事項 | 仕様・証拠 |
|---|---|
| 位置 | `MouseInput.tTryGetLogicalPoint` は画面座標を `ScreenToClient` でクライアント座標へ変換し、クライアント幅W・高さHに対して `x = trunc(clientX × 1920 / W)`、`y = trunc(clientY × 1080 / H)`。truncは0方向、範囲外をクランプしない。縦横別倍率で、レターボックス補正はない。 |
| 失敗・ボタン | ハンドルなし、API失敗または幅/高さ≤0なら位置保持・移動量0。ボタンは前回と今回のbit比較でedge/release、holdは現在bit。ホイールは累積をリセットする取得を1フレーム1回。 |
| DPI | 上式はWindows APIが返す同一座標系の値を前提とする。ゲームのDPI awarenessと複数モニター移動時の仮想化・実寸の互換性はこの章では未確定。テスト補助のDPI設定をゲーム本体の設定と同一視しない。 |

## 受入ケース

| 入力・条件 | 期待結果 |
|---|---|
| キーを3更新押し続け解放 | カウンタ1,2,3,0；edgeは1回、holdは3回。 |
| 33と34を同じ面左へ割当し同時押下 | スロットedgeは真1個であり2打を意味しない。 |
| 1P面左右と縁左右を同フレーム押下 | 4 edgeを記録し、通常の打撃処理は面左1回＋縁左1回。 |
| 再割当で1P面を別キーに変更 | 演奏には新キーが効く。固定UIの32/37等は変更されない。 |
| 接続時からボタン押下 | 初回はedgeなし・hold真。解放して再押下した更新でedge。 |
| switch ↑から↗へ直接遷移 | ↗のedge成立、↑のholdは不成立。 |
| 軸だけを動かし戻す | この入力層では割当edgeなし。軸閾値・帰還判定を創作しない。 |
| 同VID/PID機器2台の順序反転 | ordinalが入れ替わり、物理個体との対応は保持される保証がない。 |
| 通常EnterとテンキーEnter | 28と156として別扱い。Pauseは197。PageUpは201でありテンキー9の73ではない。 |
| 960×540クライアントの点(480,270) | 論理座標(960,540)。外側の負座標も切捨て方向とクランプなしを検証。 |
| DPI 100%/150%、モニター間移動 | 表示とヒット座標が一致するか実機検証。未検証を確定扱いしない。 |
